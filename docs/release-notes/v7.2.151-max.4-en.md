# CPA Manager Plus v7.2.151-max.4

> Fork prerelease based on v1.12.12

> [Chinese ->](https://github.com/2ue/CPA-Manager-Plus/blob/v7.2.151-max.4/docs/release-notes/v7.2.151-max.4-zh.md)

## Overview

v7.2.151-max.4 merges upstream v1.12.12 into the fork baseline while preserving the fork's own features. It also repairs the release toolchain: the update-channel contract introduced upstream structurally rejected `-max.N` tags, and now supports them.

## Highlights

### Features

- The accounts list gains a card view, and quota windows lay out responsively across mobile and laptop screens.
- Adds Manager update checks with a notification page, and publishes verified update channels after a release.
- Supports inline priority and note editing with blur auto-save; batch quota refreshes are protected against rate limits.
- The Codex reset-credits badge links straight to its detail anchor.

### Fixes

- Reset-card results are handled fail-closed, syncing gateway cooldown only on an explicit success.
- Unconfirmed xAI quota is no longer displayed, and paid-plan detection uses a strict gate.
- List quota usage and forecasts survive tab switches in the detail drawer.
- The external panel update check is hardened against stale-response races.

### Release Tooling

- The update contract recognises a `max` stage, so tags like `v7.2.151-max.4` no longer fail with `Invalid release identity`.
- `max` is a closed train: fork builds never enter the stable / rc / beta channels, and an upstream stable is never offered as an update to a max install.
- Repository and image identity are no longer hard-coded to upstream. They resolve from `GITHUB_REPOSITORY` / `CPAMP_REPOSITORY_SLUG`, and behave exactly as upstream when unset.

## Upgrade Notes

- This is a fork prerelease tagged `v7.2.151-max.4` and requires no manual migration.
- `management.html` is now produced by the build instead of being committed. Custom deployments can point at one with `PANEL_PATH`.
